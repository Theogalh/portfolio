Ce que ça fait

Les captures collées dans les conversations finissent en pièces jointes que personne ne retrouve. screen les transforme en liens : déposez l’image, récupérez une URL qui charge vite depuis un CDN, dessinez dessus s’il faut montrer quelque chose, et passez-la en privé quand elle n’est pas pour tout le monde.

Glisser-déposer

Une seule zone de dépôt. Les fichiers sont validés côté serveur et refusés avec un message clair quand ce ne sont pas des images.

Miniatures

Chaque capture reçoit une miniature pour la galerie, servie avec les mêmes en-têtes de cache longue durée.

Annoter

Ouvrez une capture dans le canvas, dessinez, enregistrez. La version annotée garde sa propre URL, et le dessin peut être rouvert plus tard.

Public ou privé

Un interrupteur par capture. Les captures privées ne sont accessibles qu’à leur propriétaire.

Supprimer une fois fini

Un seul appel retire l’objet, la miniature, le canvas et les métadonnées.

Du dépôt au lien

Déposez une image sur la page.
Le serveur la valide, l’envoie vers le stockage objet, fabrique une miniature.
Les métadonnées (identifiant, nom, visibilité, dates) partent dans Redis.
La galerie affiche la miniature ; le lien pointe vers le CDN.
Optionnel : ouvrez le canvas, dessinez, enregistrez les opérations et l’image rendue.
Passée la fenêtre de rétention, tout ce qui porte cet identifiant est supprimé.

Architecture

Une arborescence theoproject standard. Le module screenshots est le seul module métier ; le stockage vient d’un snippet versionné.

layout
app/          config · main (lifespan opens Redis + uploader) · router
modules/
  health/     GET /health — Redis ping
  screenshots/
    controller.py   routes, rate limits, HTTP mapping
    service.py      upload · list · canvas · visibility · delete
    schemas.py      ScreenshotResponse, CanvasSaveRequest, …
theolib/storage/    snippet: S3 uploader, image validation, CDN URLs
cache/        RedisClient + key builder
web/          Jinja2 SSR, GET /
static/ templates/ deploy/ .github/

Décisions

  • Injection par constructeur, pas de globalesLes services reçoivent l’uploader, le store et le réglage de rétention. Les contrôleurs construisent le service à chaque requête depuis app.state.
  • Une validation, c’est un 422, pas un 500ImageValidationError venu du snippet de stockage se traduit en 422 avec le motif. Les mauvais fichiers n’atteignent jamais le bucket.
  • Les annotations sont d’abord des données, ensuite des pixelsLe canvas est enregistré comme une liste d’opérations plus une image rendue. La liste le rend modifiable ; l’image le rend partageable.
  • Immuable par constructionL’identifiant est la clé de cache, donc Cache-Control: public, max-age=31536000, immutable est sans risque. Une image modifiée est un nouvel identifiant.
  • Le stockage est un snippet, pas une copietheolib/storage est installé et épinglé par theoproject ; les correctifs sortent sous forme de tag et se récupèrent avec theoproject update storage.
